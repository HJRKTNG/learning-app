学習アプリ — 画面遷移とワイヤーフロー

「毎日16:00に対象アプリをロック → 数学ミッション（10問中8問正解）で解除 → 翌日16:00まで自由利用」という制御を、状態と遷移として整理したラフ案です。まだ作り込みではなく、構造と分岐を固めるのが目的です。

この段階での前提・設計判断

  • 状態は大きく 自由（16:00前） / 制限中（学習） / 解除済み の3つ。
  • 合格ライン = 10問中8問正解（正答率80%）。初回で未達でも、間違えた問題の再挑戦で累計8問に到達すれば解除。
  • 解答は紙に書く前提 → 撮影 → OCR → AI採点 の1問フローを軸にしています。
  • 教科は数学中心ですが、ミッションの器は他教科にも流用できる構造にしています。
  • ※ ビジュアルは最終形ではありません。レイアウト・遷移・情報量の確認用です。

次に決めたい論点

  1. 合格判定は「初回10問のみ」で見るか、「再挑戦込みの累計8問」で見るか（本案は累計派）。
  2. 再挑戦は同じ問題か類題か。
  3. AI採点が不確かなとき（読み取り不能）の扱い — 再撮影 / 手動確認 / スキップ。
  4. 16:00前に先回りして解くのを許可するか（「今日の範囲を先に見る」の挙動）。
  5. ヒントを使った問題を正解扱いにするか。
